# arch-review — アーキテクチャ準拠チェック（check-only）

[docs/layer-architecture-guide.md](../../../docs/layer-architecture-guide.md)（完成形の基準）と
[docs/implementation-workflow-guide.md](../../../docs/implementation-workflow-guide.md)（2フェーズ手法）に基づき、
コードの準拠状況を判定してレポートする。

**このスキルはチェックと報告のみを行う。ファイルの修正・移動は行わない。**
修正が必要な場合はレポートに推奨対応を記載し、フェーズ2タスクとして別途指示を受ける。

## 手順

### 1. スコープの決定

- 引数（`$ARGUMENTS`）でパスやスライスが指定されていればそれを対象とする
- 指定がなければ `src/` 全体を対象とする

### 2. PHASE1 スライスの棚卸し

`src/` 全体を `PHASE1` で Grep し、未振り分けスライスの一覧を作る（スコープ指定があっても棚卸しは全体で行う）。

### 3. 判定基準の振り分け

スライスごとに適用する基準を切り替える（implementation-workflow-guide.md の線引き表に従う）:

| 対象 | 適用する基準 |
|---|---|
| `PHASE1` マーカー付きスライス | **常時適用ルールのみ**（依存方向・BFF 経由・shared 純粋性・コーディング規約）。配置ルール違反は違反として扱わず「振り分け待ち」として報告する |
| マーカーなしのコード | **アーキテクチャガイドの全基準** |

### 4. チェック項目

インポートは `#/レイヤー名/...` のパスエイリアス形式なので、Grep で機械的に検出できる。

**依存方向（禁止パターン1・2）— 常時適用**
- 各レイヤーのファイル内で、上位レイヤーへの import を検索する
  （例: `entities/` 内で `#/features/`・`#/widgets/`・`#/aggregates/` を Grep）
- 同レイヤーの別スライスへの import を検索する
  （例: `entities/order/` 内で `#/entities/` を Grep し、自スライス以外への参照を確認。composite → atomic の一方向のみ許可、詳細はアーキテクチャガイドの entities セクション参照）

**BFF 経由（禁止パターン5・8）— 常時適用**
- `routes/api/` 以外での外部 URL への fetch を検索する（`fetch(` を Grep し、`/api/` 以外への直接リクエストがないか確認）
- FSD レイヤーから `routes/api/` への直接 import を検索する

**shared の純粋性（禁止パターン3・4）— 常時適用**
- `shared/` 内の `fetch(`・ドメイン型の import を検索する

**コーディング規約 — 常時適用**
- `brand<` および ` as `（型アサーション）が `adapters.ts` 以外に存在しないか
- 非 null アサーション `!` が使われていないか
- `function` 宣言が使われていないか（const + アロー関数のみ）
- `Raw` プレフィックス・`Atom` サフィックス・レイヤー命名規則（features は動詞+名詞、widgets/entities は名詞）

**配置ルール — マーカーなしのコードのみ**
- 決定フローチャートどおりの配置か（UI・BFF リクエスト・atom）
- widgets の内部構成制約（atoms.ts / types.ts / adapters.ts の同居がないか、データ取得の3条件）
- 禁止パターン7（下位レイヤーで完結できるのに上位に置いていないか）
- 外部非公開ファイルを持つスライスに `index.ts` があるか
- `routes/` と `pages/` の 1対1 対応

### 5. レポート出力

以下の形式で報告する:

```
## アーキテクチャ準拠レポート

**判定: 合格 / 不合格**（スコープ: xxx）

### PHASE1 未振り分けスライス（棚卸し）
| スライス | 同居ファイル | 備考 |

### 違反（マーカーなしコードの基準違反 + 常時適用ルール違反）
| 重大度 | ルール | 該当箇所 (file:line) | 内容 | 推奨対応 |

### 補足
（グレーゾーンの判断・フェーズ2実施時の注意点など）
```

- 重大度: **高**（依存方向・BFF バイパス・型安全性）/ **中**（配置・命名）/ **低**（推奨事項）
- 該当箇所は必ず `file:line` 形式で示す
- 違反ゼロかつスコープ内に PHASE1 マーカーがない場合のみ「合格」とする
- PHASE1 スライスの存在自体は違反ではないが、スコープ内に残っている場合は「不合格（振り分け待ちあり）」として区別する
